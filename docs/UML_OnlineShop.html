UML Diagramme - OnlineShop

1. Entity-Klassen und ihre Beziehungen

Dieses Diagramm zeigt alle Daten-Entitäten (Entity-Klassen) des Online-Shops und deren Beziehungen zueinander.

  • User ↔ Cart (1:1) — Jeder Benutzer hat genau einen Warenkorb
  • User ↔ Order (1:N) — Ein Benutzer kann mehrere Bestellungen haben
  • Order ↔ OrderItem (1:N) — Eine Bestellung enthält mehrere Positionen
  • OrderItem speichert unitPrice — Preis wird zum Bestellzeitpunkt eingefroren
  • Category ↔ Product (1:N) — Ein Produkt gehört zu einer Kategorie

2. Service-Schicht (Business-Logik)

Services sind zustandslos (Stateless) und rufen einander auf. OrderService benutzt CartService und ProductService für den Checkout-Prozess.

classDiagram direction TB class UserService { +register(dto): UserResponseDto +findByEmail(email): User +updateProfile(id, dto): UserResponseDto } class ProductService { +findAll(pageable): Page +search(name, category): List +findById(id): ProductResponseDto } class CartService { +getCart(userId): CartResponseDto +addItem(userId, productId, qty): void +removeItem(cartId, itemId): void +clearCart(cartId): void } class OrderService { +checkout(userId, dto): OrderResponseDto +findByUserId(userId): Page +changeStatus(id, newStatus): void } class PriceCalculatorService { +calculateTotal(items): BigDecimal +calculateSubtotal(product, qty): BigDecimal } class AnalyticsService { +getRevenueByMonth(year): List +getTopProducts(limit): List } OrderService --> CartService OrderService --> ProductService OrderService --> PriceCalculatorService CartService --> ProductService

Alles läuft in einer einzigen @Transactional-Transaktion.
